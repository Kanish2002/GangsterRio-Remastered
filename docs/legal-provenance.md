# Rights and provenance

A user supplied a Java ME game for private inspection and browser-local testing. Supplying a file is not evidence of redistribution or modification permission. The inspected manifest indicates repackaging; lawful acquisition and original authenticity have not been established independently. No proprietary JAR, JAD, extracted resource, decompiled source, or gameplay recording is committed or deployed.

The site accepts only local file import. File bytes go to browser IndexedDB and CheerpJ's persistent virtual filesystem, not this site's server. JAD URLs are not followed. The host's game-installation key derives from a SHA-256 checksum. Users must hold the necessary rights for their own use.

The distribution serves corresponding source for the modified runtime at `/runtime/freej2me-web-source.tar.gz`, upstream license at `/runtime/LICENSE`, and custom bridge source at `/runtime/host-source/org/rio/HostBridge.java`. Packaged sample games are removed from the playable runtime. Unrelated sample media and sample-game archives are omitted from both deployed runtime and corresponding source. The original upstream MIDI bank was identified as copyrighted Roland material with no redistribution grant established. The build replaces the complete embedded bank and its source/header with original, mathematically synthesized GPL samples. The substitution code and notice are included in corresponding source. This changes MIDI timbres; it does not alter game event timing or MIDI note sequences.

The project is not an official Gameloft product. Existing title references identify a compatibility target and do not confer asset rights. Commercialization or original-asset enhancement requires separately established permissions. Neither original game rights nor complete Java ME emulator compatibility are implied.

The corresponding-source bundle also includes FFmpeg n7.1.1 and x264 commit fe9e4a7f39d7a9fd208e4592238f9809d5936439, which upstream media build scripts otherwise fetch externally. Archive SHA-256 checks bind these versions; the upstream x264 patch is applied. Their COPYING/LICENSE files are retained. This is a source-completeness improvement, not a change to the media decoder binary.
